# Operate and troubleshoot Ultra-Doc

Use this guide after the [local setup](../README.md#run-a-local-example).
Run every command from the target project's root with `ULTRA_DOC_SCRIPTS`
pointing to the separate plugin checkout's `skills/ultra-doc/scripts` directory.
Create `context_for_llms/`, `context_for_humans/`, and `reports/` first.
The scripts operate locally and can modify files; review changes in Git before
committing them.

## Choose an action

All orchestrator actions start and finish with documentation state analysis.
Set `ULTRA_DOC_AUTO_ACTION` explicitly for unattended runs. Unknown values are
ignored, allowing normal automatic selection to run instead.

| Action | Work performed | Important limits |
| --- | --- | --- |
| `sync` | Tracks code changes; syncs metadata, formatting, lint, overlays, human overviews, parity, changelog, and report; then validates references and examples. | Modifies source Markdown as well as generated files. The summary is written before final validation and final state analysis. |
| `quick` | Updates timestamps, autofixes formatting, writes a lint digest with parity checking skipped, then regenerates human overviews. | Does not regenerate section/pointer/relationship overlays, validation, changelog, or summary. |
| `validate` | Tracks code changes and validates code pointers, selected file references, and simple example patterns. | Writes state, change-tracking output, and validation results; does not rewrite incorrect prose or refresh overlays. |
| `summary` | Generates `reports/ultra-doc-summary.md` from available artifacts. | Refreshes state but uses existing lint/validation artifacts. Missing results are shown as unknown; success does not prove validation passed. |

For example, run reference checks with:

```bash
ULTRA_DOC_AUTO_ACTION=validate node "$ULTRA_DOC_SCRIPTS/orchestrator.mjs"
```

After a successful sync, rerun `summary` to include the final validation and
state results in the report. The lint digest's embedded validation snapshot
still reflects the artifacts available when linting ran.

The Node CLI reads `ULTRA_DOC_AUTO_ACTION`, not command-line action arguments.
It has no `--sync`, `--help`, or `install` argument parser. Without an accepted
preset it can run full sync automatically for stale docs or choose a default
menu action in a noninteractive process.

## Inspect generated output

| Location | Contents and behavior |
| --- | --- |
| `context_for_llms/SECTIONS.json` | Section content and line ranges from top-level machine Markdown. |
| `context_for_llms/CODE_POINTERS.json` | Generated `{ generated, total_entries, pointers }` envelope linking sections to source paths; older flat input mappings are also accepted. |
| `context_for_llms/RELATIONSHIPS.json` | Relationships inferred from local documentation links. |
| `context_for_llms/INDEX.md` and `context_for_llms/llms.txt` | Navigation generated by metadata sync. |
| `context_for_llms/DOC_STATE.json` | Heuristic completeness, file modification time freshness, and percentage of documents with pointers. This is not source-code test coverage. |
| `context_for_llms/CODE_CHANGES.json` | Changes from recent Git history (30 days) when Git is available. The fallback uses source file modification times and does not create the same Git report. |
| `context_for_llms/VALIDATION.json` | Errors, warnings, and per-document check score. Errors make validation exit nonzero; warnings alone do not. |
| `context_for_llms/LINT_WARNINGS.md` | Lint warnings plus validation and parity snapshots. Errors make lint exit nonzero; warnings alone do not. A digest is written before either result. |
| `context_for_humans/` | Generated top-level Markdown overviews, excluding `INDEX.md`. Parity compares file existence and modification times, not factual equivalence. |
| `changelog/docs-YYYY-MM-DD.md` | Appended lists of changed documentation files detected through Git. No entry is created when no changes are detected. |
| `reports/ultra-doc-summary.md` | Summary of the available artifacts. |

The humanizer also writes prompt-debug text containing the full source document.
It lives in the target project's `logs/ultra-doc/`, following the containment
repair in [PR #5](https://github.com/justfinethanku/ultra-doc/pull/5). These are local debug files;
there is no AI request behind the logged prompt.

## Configure the project

The orchestrator checks for `.ultra-doc.config.json` and reads its `version` for
an upgrade notice when target package/plugin version metadata is available.
The setup skill records `setup_level`, `audience`, `ci_integration`, and
`installed_at` as setup metadata. The deterministic scripts do not use those
fields to filter documents, choose a writing style, or create CI jobs.
`ignore_patterns` and `human_doc_style` are not implemented settings.

The supported script environment controls are:

- `ULTRA_DOC_AUTO_ACTION=sync|quick|validate|summary`: selects an orchestrator action.
- `ULTRA_DOC_SKIP_PARITY=1`: skips the linter's parity check. Full sync sets this
  during linting and verifies parity after generating human overviews. Quick
  mode also skips the lint parity check.

No environment file or service credential is required for these local actions.

## Recover from a failed run

| Symptom | Check and recovery |
| --- | --- |
| `Ultra-Doc is not installed in this repository` | Confirm the current directory is the intended target and create its configuration and documentation folders. This message exits zero without doing setup; it is not an installation receipt. |
| `Documentation directory not found` | Create `context_for_llms/` and add real Markdown before analyzing. Installing the plugin alone does not create it. |
| `ENOENT` for `reports/ultra-doc-summary.md` | Create `reports/` in the target project, then rerun the selected action. |
| `/ultra-doc: No such file or directory` | A Claude slash command was run by a shell. Invoke it inside Claude Code or run the Node orchestrator with an explicit preset. |
| `import: command not found` or a syntax error at `const` | Run `.mjs` scripts with Node.js instead of Bash. |
| `Metadata sync failed` or `Orchestrator failed` | Inspect the first failing child script. A failed sync can leave partial output; correct the input and rerun full sync. There is no automatic rollback. |
| Validation errors after `Sync Complete` | The metadata stage completed, but final validation did not. Read `VALIDATION.json`, correct broken references/examples, then rerun validation. |
| Unexpected stale-doc or parity status after copying/restoring files | Freshness and parity use modification times. Inspect actual source changes; these scores are review hints, not semantic validation. |
| Hooks do not run | The legacy root hook file is not registered by the plugin. Use explicit commands; see [FLEET-670](https://linear.app/contentionmedia/issue/FLEET-670). |

To undo an unwanted run, inspect `git status` and `git diff`, then restore only
changes you intend to discard from a known good commit. Generated human docs
are not a backup of the original source. Keep unrelated edits intact.

## Verification boundary

The documentation audit executed marketplace add/install/update and component
inventory in an isolated Claude configuration, plus the Node workflows in fresh
local projects. It did not run a conversational Claude session, automatically
install CI, or fire lifecycle hooks. For current plugin mechanics, consult the
[Claude Code plugin documentation](https://code.claude.com/docs/en/plugins) and
[hooks reference](https://code.claude.com/docs/en/hooks).
